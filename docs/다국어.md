# 다국어 — 아직 하지 마라, 다만 지금 알아둘 것

**결론부터: 지금 착수하면 순서가 거꾸로다.** 결과 노드가 19개인데 번역부터 하면
틀린 것을 3배로 늘리는 일이 된다. 이 문서는 **언제, 무엇을, 어떤 위험을 안고** 하는지를
미리 적어두는 것이지 착수 신호가 아니다.

목표는 **3개국 × 3개 언어 = 9가지 조합**이다.
한국 사람이 미국 정치를 한국어로 보고, 일본 사람이 한국 정치를 일본어로 본다.

---

## 1. 콘텐츠와 언어는 별개다

이 둘을 하나로 묶으면 처음부터 막힌다.

| | 뜻 | 값 |
|---|---|---|
| **콘텐츠** | 어느 나라 정치를 보는가 | `kr` `us` `jp` |
| **언어** | 무슨 말로 읽는가 | `ko` `en` `ja` |

`/kr?lang=ja` 는 **한국 정치를 일본어로** 본다는 뜻이다.
"일본어니까 일본 정치"가 아니다. 이걸 섞으면 9칸 표가 3칸으로 쪼그라든다.

**사이트 이름도 나라별로 다르다.** 한국 `왜` · 미국 `WHY` · 일본 `なぜ`.
번역이 아니라 **같은 브랜드의 현지 이름**이다. 세 이름 모두 "왜"라는 한 글자 질문이라는 점이 같다.
지금 한국판 이름은 `왜` 그대로 둔다.

**언어는 접속 국가로 추정하되 사용자가 바꿀 수 있어야 한다.**
추정은 `navigator.language` 로 하고, 고른 값은 저장한다.
자동 판단만 있으면 해외 교민·유학생·연구자가 막힌다. 추정은 기본값이지 결정이 아니다.

## 2. 지금 데이터가 어떻게 생겼나 (실측)

추측이 아니라 실제로 세어본 값이다.

```
노드 231개 · 관계 307개 · 노드 필드 53종
데이터 영역 한국어 문자열   2,237개
로직 영역 한국어 문자열       434개
HTML/CSS 영역 한국어 조각     995개
```

### 노드 필드 53개 중 번역이 필요한 것

**번역 대상 — 사람이 읽는 글 (16종)**

| 필드 | 개수 | 무엇 | 난이도 |
|---|---|---|---|
| `lab` | 231 | 노드 이름 · 화면 이름표 | 고유명사 다수 → **인용** |
| `tip` | 231 | 한 줄 요약 | 번역 |
| `body` | 231 | 본문 설명 | 번역 · 분량 최대 |
| `src` | 231 | 출처 표기 | **인용** (기관명) |
| `sub` | 96 | 부제 (소속·직위) | **인용** |
| `kind` | 93 | 종류 (법률/시행령 등) | 용어 사전 |
| `ekind` | 90 | 사건 종류 | 용어 사전 |
| `title` | 26 | 법안 제목 (쉬운 말) | 번역 |
| `off` | 26 | 공식 법령명·공포일 | **인용 필수** |
| `story` | 26 | 단계별 설명 (배열) | 번역 |
| `eff` | 26 | 무엇이 달라졌나 (배열) | 번역 |
| `limit` | 22 | 남은 문제·비판 (배열) | 번역 · **가장 위험** |
| `cap` | 19 | 숫자 설명 | 번역 |
| `big` | 19 | 큰 숫자 | 숫자 형식만 |
| `career` `edu` `pre` `quote` `counter` `warn` `pending` | 소수 | 인물 이력·해명 | **인용/번역 혼합** |

**번역 불필요 (37종)** — `id` `t` `side` `cats` `yr` `owner` `ghost` `prez` 같은
구조·좌표·물리 필드. 그리고 `x` `y` `vx` `vy` `r` `a` `gl` `__hw` `__hh` 등 런타임 값.

### 관계 배열 `L` 은 칸 단위로 갈린다

```
['b1','r1','시행 17년 뒤','result','{a} 시행 이후 {b}가 됐습니다',1,'2005 시행 → 2022']
   ↑      ↑        ↑ 번역        ↑ 구조      ↑ 번역(템플릿)      ↑     ↑ 번역
  구조   구조                                                  구조
```

**`l[2]`(라벨)와 `l[4]`(문장)와 `l[6]`(시점 설명) 세 칸이 번역 대상**이고
`l[0] l[1] l[3] l[5]` 는 구조라 그대로 둔다.

`l[4]` 는 `{a}` `{b}` 치환 템플릿이다. **한국어는 조사가 앞 글자 받침에 따라 바뀐다**
(`{a}가` / `{a}이`). 영어·일본어는 어순 자체가 달라서 템플릿을 언어별로 따로 써야 한다.
이건 문자열 치환이 아니라 **문장 생성 규칙의 문제**다.

## 3. `{ ko, en, ja }` 로 바꿀 때 깨지는 곳

노드 텍스트를 `lab: '외국인 유권자 12.6만'` 에서
`lab: { ko:'…', en:'…', ja:'…' }` 로 바꾸면 아래가 전부 영향을 받는다.

### 가장 크게 깨지는 곳 — 캔버스 렌더링

**여기가 최대 위험 지점이다.** 이유가 셋이다.

1. **글자 폭이 언어마다 다르다.** 지금 이름표 겹침이 이미 280~290쌍이다.
   영어는 같은 뜻에 글자 수가 1.5~2배가 된다. `외국인 유권자 12.6만` → `126,668 foreign voters`.
   **번역하는 순간 겹침이 폭발한다.** 이름표 겹침(A 단계)을 먼저 풀지 않으면
   영어판은 읽을 수 없는 화면이 된다.
2. **`measureText` 가정이 무너진다.** `test/check.cjs` 의 폭 계산은 전각/반각을 나눠 센다
   (전각 1.0em, 반각 0.52em). 일본어는 전각이라 한국어와 비슷하지만 영어는 다르다.
   검사 스텁도 언어별로 검증해야 한다. — CLAUDE.md "검사를 검사한다" 3번 사례가 정확히 이것이었다.
3. **줄바꿈 규칙이 다르다.** 한국어·일본어는 `word-break:keep-all` 로 어절 단위,
   영어는 공백 단위다. 지금 `.hint` `.uselist` 등에 `keep-all` 이 박혀 있다.

### 그 밖에 손대야 하는 곳

| 어디 | 무엇 | 규모 |
|---|---|---|
| 노드 렌더 (`render()`) | `n.lab` `n.body` … 를 읽는 모든 줄 | 큼 |
| 검색 (`qSearch`) | 검색 대상 문자열 결합. **선택 언어만 볼지 전 언어를 볼지 결정 필요** | 중 |
| 분야 자동 분류 (`AUTOCAT` 15종) | 한국어 키워드 매칭. 언어별 키워드 필요 | 중 |
| 화면 상수 | `TK`(6) `SIDEN`(7) `KINDN`(4) `CATS`(19) `SRCK`(4) | 작음 · 55개 |
| HTML 고정 문구 | 995조각 (제목·부제·안내문·'보는 법'·라이선스) | 중 |
| `<head>` 메타 | `title` `description` `og:*` — 언어별로 달라야 한다 | 작음 |
| `og.png` | 나라·언어별로 따로 만들어야 한다 | 작음 |
| 정렬·형식 | 숫자·날짜 형식(`126,668명` / `126,668 people`), 연호(일본 `令和`) | 중 |

**폴백 규칙이 필요하다.** 번역이 없는 필드는 원문을 보여줄 것인가, 그 노드를 숨길 것인가.
**원문 노출이 맞다** — 숨기면 인과 사슬이 끊겨서 지도가 거짓말을 한다.
대신 "이 항목은 아직 한국어 원문입니다" 라고 화면에 밝힌다.

## 4. 번역 방식 — 선택지와 위험

### 원칙 0-B와 정면으로 충돌한다

> **LLM이 생성한 텍스트를 사실 출처로 쓰지 않는다.**

자동 번역은 이 원칙을 정통으로 건드린다.
**틀린 번역은 "출처는 정확한데 내용이 틀린 상태"를 만든다.**
이게 이 프로젝트에서 가장 나쁜 실패다 — 링크를 눌러 원문을 확인해도
번역문이 틀렸다는 걸 알 수 없기 때문이다. 오히려 원문 링크가 틀린 문장을 보증해 준다.

없는 출처보다 나쁘다. **없는 출처는 의심받지만, 틀린 번역은 신뢰받는다.**

| 방식 | 비용 | 위험 | 판단 |
|---|---|---|---|
| **기계 번역 그대로** | 매우 낮음 | **치명적.** 법률 용어를 태연히 오역한다. 규칙 1·2와 충돌 | **안 된다** |
| 기계 번역 + 사람 검수 | 중 | 검수자가 그 나라 정치를 모르면 오역을 못 잡는다 | 조건부 |
| 사람 번역 (전문) | 높음 | 낮음 | 소량에는 맞다 |
| **공식 명칭 인용 + 설명문만 번역** | 중 | 낮음 | **이게 맞다** |

### 왜 "인용"이 답인가

**법령명·기관명·인물명은 번역이 아니라 인용해야 한다.**

- **법제처가 영문 법령명을 제공한다.** `공직선거법` → `Public Official Election Act`.
  이건 우리가 지어낸 번역이 아니라 **정부가 공표한 공식 명칭**이다.
- **정부 기관도 공식 영문명이 있다.** 국가정보원 → `National Intelligence Service`.
- **인물명은 로마자 표기 규칙과 본인 표기가 다를 수 있다.** 공식 표기를 따른다.

**그건 번역이 아니라 인용이라 규칙 1·7과 충돌하지 않는다.**
출처를 댈 수 있고, 틀리면 원 출처가 틀린 것이다. 우리가 지어낸 게 아니다.

그래서 필드를 두 부류로 나눈다:

- **인용 필드** — `off` `src` `sub` `kind` 그리고 `lab` 중 고유명사.
  공식 명칭이 확인된 것만 넣고, 없으면 **원문 + 로마자 병기**로 두고 `확인 중` 표시.
- **번역 필드** — `tip` `body` `story` `eff` `cap`.
  우리가 쓴 설명문이라 번역해도 원 사실이 훼손되지 않는다.

**`limit`(남은 문제·비판)이 가장 위험하다.** 정치적으로 민감한 문장이고,
뉘앙스가 조금만 어긋나도 한쪽 편을 드는 문장이 된다.
규칙 5가 지키려는 균형이 번역에서 깨질 수 있다. **여기만은 사람 번역이 필요하다.**

### 강제할 것

번역을 시작하면 `test/check.cjs` 에 이런 검사가 필요하다.

- 인용 필드에 **출처 없는 번역이 들어가면 FAIL** (공식 명칭 출처 필수)
- 언어별로 **이름표 겹침·화면상 글자 크기를 각각** 측정
- 폴백이 일어난 노드 수를 **분모와 함께** 출력 (`영어 번역 없음 47/231`)
- 언어를 바꿔도 **노드·관계 개수가 같은지** (번역 누락으로 노드가 사라지면 안 된다)

## 5. 언제 착수하나

**지금은 아니다.** 순서가 있다.

```
1. 결과 노드 19개 → 충분히          ← 지금 여기. 진짜 병목
2. 이름표 겹침 280~290쌍 해소        ← 영어는 글자가 길어 이걸 안 풀면 무너진다
3. 창고(SQLite)/지도 분리            ← 번역은 행 단위 관리가 필요하다
4. API 수집기                        ← 데이터가 자동으로 들어와야 번역 대상이 안정된다
5. 다국어                            ← 여기
```

**3번이 특히 중요하다.** 지금은 데이터가 `index.html` 안에 있다.
번역을 여기에 넣으면 파일이 3배가 되고, 어느 문장이 언제 누구에 의해 번역됐는지
추적할 방법이 없다. **번역도 출처가 필요한 데이터다** — 누가 언제 무엇을 근거로 옮겼는지.
그건 파일 하나로는 감당이 안 된다.

**착수해도 되는 신호:**

- 결과 노드가 충분해서 "한국판이 완성됐다"고 말할 수 있을 때
- 이름표 겹침이 풀려서 글자가 길어져도 화면이 견딜 때
- 창고가 분리되어 번역문마다 출처와 시각을 붙일 수 있을 때
- 법제처 영문 법령명을 **자동으로 가져올 경로**가 확인됐을 때 (수작업이면 곧 멈춘다)

**먼저 해도 되는 것 하나:** 구조만 미리 열어두는 것.
`lab: '…'` 을 `lab: { ko: '…' }` 로 바꾸는 건 지금 해도 손해가 없고,
나중에 `en` `ja` 를 붙이기만 하면 된다. 다만 **이것도 결과 노드가 채워진 뒤에** 한다.
231개를 두 번 만지느니 400개를 한 번 만지는 게 낫다.

## 요약

- 콘텐츠(`kr`/`us`/`jp`)와 언어(`ko`/`en`/`ja`)는 별개다. 9칸 표다.
- 노드 필드 53종 중 **번역 대상은 16종**, 나머지는 구조·좌표다.
- 관계 `L` 은 7칸 중 **3칸(`l[2]` `l[4]` `l[6]`)만** 번역 대상이다.
- **가장 크게 깨지는 곳은 캔버스 이름표다.** 영어는 글자가 1.5~2배 길고
  겹침이 이미 280~290쌍이다. 이걸 먼저 풀어야 한다.
- **법령명·기관명·인물명은 번역이 아니라 인용한다.** 법제처 영문 법령명이 있다.
  인용은 출처를 댈 수 있어서 규칙 1·7과 충돌하지 않는다.
- **자동 번역은 원칙 0-B와 정면 충돌한다.** 틀린 번역은 출처가 정확한 채로 내용만 틀린
  상태를 만든다. 없는 출처보다 나쁘다 — 없는 출처는 의심받지만 틀린 번역은 신뢰받는다.
- **지금 착수하지 않는다.** 결과 노드 19개가 먼저다.
