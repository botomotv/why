# 인물 카드 · 법안 카드 설계

수집이 끝나면 카드에 담을 게 갑자기 많아진다.
**많아지는 순간이 제일 위험하다.** 목록으로 늘어놓기만 해도 화면이 채워지기 때문에,
"무엇을 안 보여줄지" 를 정하지 않으면 안 정한 채로 다 보여주게 된다.

구현 전 설계 문서다. 아직 코드는 없다.

---

## 0. 먼저 — 화면 설계로 못 막는 것이 있다

### 이 사이트는 정적이다. 데이터 파일이 통째로 공개된다

법안 카드에 찬성자 이름을 안 늘어놓기로 했다. 맞는 판단이다.
**그런데 그것만으로는 명단이 안 만들어지는 게 아니다.**

서버가 없으니 지도는 JSON 을 통째로 받아서 그린다.
`data.json` 에 개인 표결이 들어 있으면 **주소창에 파일 이름만 치면 전부 나온다.**
화면에 안 그렸을 뿐이다.

```
화면에 안 보임  ≠  가질 수 없음
```

**그래서 이건 UI 결정이 아니라 내보내기 결정이다.**

| 결정해야 할 것 | 뜻 |
|---|---|
| 개인 표결을 내보내는 파일에 **넣는가** | 넣으면 누구나 전량을 받는다 |
| 넣는다면 **어느 파일에** | 인물별로 쪼개면 전량 수집에 품이 든다 |
| 안 넣는다면 인물 카드의 표결 목록은 **어디서 오나** | 인물별 파일이 따로 필요하다 |

권하는 것: **인물별 파일로 쪼갠다.**

```
data/map.json            지도. 개인 표결 없음
data/person/T2T8225E.json  그 사람 것만. 카드 열 때 받는다
```

전량을 받으려면 **3,295번 받아야 한다.** 못 막지만 늦춘다.
`map.json` 하나에 다 넣으면 한 번이면 끝난다. 차이가 크다.

**"못 막고 늦출 뿐" 이라는 걸 정직하게 안다.** 공개 기록이라 막을 수도 없고 막을 이유도 없다.
다만 **우리가 명단을 만들어 배포하는 쪽이 되지는 않는다.** 그게 이 결정의 전부다.

### 개인 표결이 없어도 소수 정당은 역산된다

정당별 집계만 내보내도, 그 당 의원이 3명이고 `찬성 2 · 반대 1` 이면
**누가 반대했는지는 세 명 중 한 명이다.** 인물 카드 세 개만 열면 확정된다.

막을 방법이 마땅치 않다 (집계를 안 내면 원래 목표가 사라진다).
**아는 채로 간다.** 다만 "정당별 집계는 개인을 감추지 않는다" 를 알고 설계한다.

## 1. 인물 카드 — 목록 버튼

이미 `.onlybtn`("이 인물만 보기 · 전체 행적 ↗")이 있다. 그 옆에 붙인다.
`index.html:3610` 근처다.

```
┌─────────────────────────────┐
│  [사진]  강경숙              │
│          22대 · 조국혁신당    │
├─────────────────────────────┤
│  [이 인물만 보기 ↗]          │   ← 지금 있는 것
│  [발의 348건] [표결 1,203건] │   ← 새로 붙일 것
└─────────────────────────────┘
```

**지도에 못 올리는 걸 목록으로 뺀다** — 이게 맞는 방향이다.
348건을 지도에 그리면 상한 6개를 58배 넘긴다. 목록은 지도의 도피처가 아니라
**지도가 감당 못 하는 양을 정직하게 인정하는 자리**다.

### 목록에서 지도로 돌아오는 길을 반드시 둔다

목록이 커지면 이 사이트는 지도가 아니라 검색 결과 화면이 된다.
목록의 각 항목은 **누르면 그 노드로 지도가 이동해야 한다.**
목록에만 있고 지도에 없는 항목은 그렇게 표시한다 — `지도에 없음 · 관계가 아직 없어서`.

## 2. 법안 카드 — 대표발의와 공동발의를 갈라놓는다

### 왜 갈라야 하나

발의에는 **10인 서명**이 필요하다. 그래서 같은 당 의원끼리 이름을 빌려주는 관행이 있고,
내용을 자세히 안 보고 서명하는 경우도 있다.

그런데 이름이 나란히 뜨면 사람들은 **"이 법을 만든 사람들"** 로 읽는다.
갈라놓지 않으면 **우리가 그 오해를 만드는 쪽**이 된다.

### 어떻게

```
발의

  대표발의   강경숙                       ← 굵게. 얼굴 있음. 누르면 지도로
  ─────────────────────────────────
  공동발의   백선희 외 9인 ▾              ← 작게. 회색. 접혀 있음
             법안을 내려면 의원 10인의
             서명이 필요합니다. 공동발의는
             그 요건을 채운 것으로,
             법안 내용에 동의했다는
             뜻은 아닙니다.
```

지켜야 할 것:

| | |
|---|---|
| 같은 줄에 놓지 않는다 | 줄이 갈리면 다른 것으로 읽힌다 |
| 같은 크기로 쓰지 않는다 | 공동발의는 한 단계 작게, 흐리게 |
| 얼굴을 나란히 놓지 않는다 | 얼굴 11개가 뜨면 그게 "만든 사람들" 이다 |
| 기본은 접어 둔다 | 펴는 건 보는 사람의 선택 |
| **설명 한 줄을 빼지 않는다** | 이게 핵심이다. 이름만 있으면 오해가 남는다 |

설명 문구는 **접힌 상태에서도 보여야 한다.** 펴야 보이면 안 편 사람은 오해한 채로 간다.

### 선도 마찬가지다

`lead_by_rst_proposer` 규칙은 **대표발의만** `push` 선을 만든다.
공동발의는 선을 만들지 않는다. [창고설계.md](창고설계.md) 5장에서 이미 정했다.
**화면과 데이터가 같은 말을 한다.**

## 3. 법안 카드 — 찬성자 명단을 늘어놓지 않는다

### 대신 정당별 집계

```
본회의 표결 · 2026-07-30

  찬성 226 · 반대 2 · 기권 0 · 불참 
  ────────────────────────────────
  더불어민주당    찬성 168  반대 0
  국민의힘        찬성  52  반대 2
  조국혁신당      찬성  12  반대 0
```

이게 원래 목표이기도 하다 — **"국민의힘은 반대했습니다" 를 자동으로 만드는 것.**
개인 표결은 인물 카드에서만 보인다.

### 계류·폐기를 대립으로 그리면 안 된다 — 실측으로 확인했다

대립 지표를 본회의 표결에서 계류·폐기로 옮기자고 했는데,
**데이터를 세어보니 그 방향이 틀렸다.**

제21대(임기가 끝나 결과가 확정된 마지막 대수) 의원발의 23,655건:

| 처리결과 | 건수 | % |
|---|---:|---:|
| **임기만료폐기** | 16,032 | **67.8%** |
| 대안반영폐기 | 5,673 | 24.0% |
| 수정가결 | 1,036 | 4.4% |
| 원안가결 | 359 | 1.5% |
| 철회 | 226 | 1.0% |
| 수정안반영폐기 | 219 | 0.9% |
| 폐기 | 110 | 0.5% |

**임기만료폐기가 기본값이다.** 대립이 아니라 시간이 지나 죽은 것이다.
"폐기됐다" 는 사실상 정보가 없다 — 셋 중 둘이 그렇게 끝난다.

그리고 **대안반영폐기 24% 는 오히려 성공에 가깝다.**
내용이 다른 법안에 흡수된 것이지 거부된 게 아니다.
이걸 '폐기' 라는 말만 보고 실패로 그리면 그것도 거짓이다.

부결은 전 대수 10만 건 중 **19건(0.02%)** 이다.

**결론: 계류·폐기는 대립 지표가 될 수 없다.** 무관심과 구별이 안 된다.

### 그러면 대립은 어디에 있나 — 정직하게 말하면 이 데이터엔 거의 없다

본회의에서는 대립이 거의 안 보인다

실제로 받은 데이터가 이렇다.

```
VOTE_TCNT 228 · YES_TCNT 226 · NO_TCNT 2
```

**226 대 2 다.** 이게 예외가 아니라 보통이다.

본회의 표결은 **마지막 단계**다. 여야가 크게 갈리는 법안은
상임위에서 멈추거나, 아예 상정이 안 되거나, 합의로 다듬어진 뒤에 올라온다.
**본회의에 올라온 시점에서 이미 걸러져 있다.**

그래서 정당별 집계만 보면 **"국회가 대체로 화목하다"** 는 인상이 남는다.
그건 사실이 아니다. 대립은 다른 곳에 있다.

| 대립 후보 | 쓸 수 있나 |
|---|---|
| 계류·폐기 | **안 된다** — 67.8%가 임기만료. 무관심과 구별 불가 |
| 부결 | **너무 드물다** — 10만 건 중 19건 |
| 본회의 반대표 비율 | 재볼 수 있다. 표결 데이터가 오면 분포부터 본다 |
| **재의요구(거부권)** | **가장 유망하다.** 명백한 대립이고 공식 기록이다. 별도 확인 필요 |
| 표결 불참 | `불참` 값이 오는지 확인 필요 |
| 필리버스터 · 안건조정위 | 이 API 에 없다 |

**재의요구가 가장 유망하다.** 대통령이 법안을 돌려보낸 것은
"재임 중" 이 아니라 **명시적 행위**라 규칙 3 에 걸리지 않는다.
`against`(반대·대립) 선을 만들 근거가 되는 몇 안 되는 공식 기록이다.
다만 이 API 에 있는지 **아직 확인 안 했다.**

### 그래서 당분간은 대립을 자동으로 못 그린다

이건 데이터의 한계가 아니라 **제도의 실제 모습**이다.
국회의 대립은 "법안이 상정조차 안 되는 것" 으로 나타나고,
그건 기록에 `임기만료폐기` 로만 남아 무관심과 섞인다.

**못 그린다는 사실을 화면에 밝히는 게 지금 할 수 있는 정직한 일이다.**
대립처럼 보이는 지표를 억지로 만들지 않는다.

**그래서 "국민의힘은 반대했습니다" 는 생각보다 드물게 나온다.**
자주 나오는 건 "모두 찬성했습니다" 다.

이걸 어떻게 다룰지는 결정이 필요하다. 세 가지 안:

- **A안** 찬반이 갈린 법안(반대 ≥ 10 같은 기준)만 집계를 강조하고 나머지는 접는다
  → 기준을 우리가 정하는 것이라 편집 판단이다. 기준을 화면에 밝혀야 한다
- **B안** 전부 똑같이 보여주고, 226:2 가 흔하다는 사실 자체를 한 줄로 설명한다
  → 정직하지만 밋밋하다
- **C안** 본회의 표결 대신 **계류·폐기**를 대립 지표로 쓴다
  → 데이터가 더 필요하다. 지금은 못 한다

**B 를 기본으로 하고 C 를 다음 목표로 둔다.** A 는 기준 자체가 주장이 된다.

### 불참을 반대로 읽지 않는다

`불참` 은 반대가 아니다. 아파서일 수도, 다른 일정일 수도, 의도적 보이콧일 수도 있다.
**우리는 구별할 수 없다.** 그러니 구별하지 않고 그대로 적는다.

`RESULT_VOTE_MOD` 에 어떤 값이 오는지 **아직 모른다.**
불참이 행으로 오는지, 아예 행이 없는지도 모른다.
수집 후 **값의 종류를 전부 뽑아서** 확인한다. 모르는 값을 '기권' 같은 걸로 뭉개지 않는다.

## 4. 인물 카드 — 표결 목록

지시하신 세 가지를 그대로 둔다.

### 찬성·반대·기권을 다 보여준다. 한쪽만 뽑는 필터를 만들지 않는다

"이 사람이 반대한 법안만" 버튼이 있으면 그 버튼이 곧 무기다.
**필터를 안 만드는 것 자체가 설계다.**

### 그 법안의 전체 표결 결과를 같이 보여준다

혼자 반대인지 당 전체가 반대인지는 **완전히 다른 사실**이다.

```
2026-07-30  ○○○ 특검법
            이 사람 · 반대
            전체 · 찬성 226 반대 2
            국민의힘 · 찬성 52 반대 2      ← 소속 당 결과도 같이
```

소속 당 결과까지 붙이는 이유: "당론과 달랐나" 가 **가장 자주 오해되는 지점**이다.
당 전체가 반대인데 혼자 반대로 보이면 개인의 성향으로 읽힌다.

**다만 이걸 강조하지는 않는다.** "당론과 달랐음" 같은 배지를 달면
그게 **배신자 찾기 도구**가 된다. 숫자를 나란히 놓기만 하고 이름은 붙이지 않는다.

### 정렬 기준을 우리가 정한다

사람이 고르게 하면 그게 무기가 된다 — 맞다. 한 가지 덧붙인다.

**어떤 정렬도 중립이 아니다.**
최신순으로 하면 최근 표결이 그 사람을 대표하고,
찬반이 갈린 것부터 하면 논쟁적인 표결이 그 사람을 대표한다.

그래서 **정렬 기준을 화면에 밝힌다.**

```
최신순으로 봅니다 · 1,203건 중 20건
```

숨겨진 기본값이 제일 위험하다. 밝혀진 기본값은 최소한 반박할 수 있다.

## 5. 더 있는 위험 — 물어보셔서 짚는다

### 5-1. 건수 자체가 순위표를 만든다

`[발의 348건]` 이라고 쓰는 순간 **348 vs 12 의 비교가 자동으로 생긴다.**
우리가 순위를 안 만들어도 보는 사람이 만든다.

그런데 **발의 건수가 많은 게 일을 잘한 게 아니다.** 자구 수정 수준의 법안도 1건이고,
몇 년 걸린 법안도 1건이다. 실적용 발의가 실재한다.

- 순위·정렬을 **건수로 하지 않는다** (의원 목록을 발의순으로 정렬하지 않는다)
- 건수 옆에 한 줄: `발의 건수는 영향력이나 성과를 뜻하지 않습니다`
- 진짜 알고 싶은 건 "가결됐나" 인데 그건 `PROC_RESULT` 로 낼 수 있다.
  `발의 348건 · 가결 12건` 이 훨씬 정직한 숫자다

### 5-2. 한 화면에 모으면 그게 신상 파일이다

발의 + 표결 + 정당 이력 + 사진 + 학력을 한 카드에 모으면,
**개별 사실은 전부 공개 기록인데 합치면 성격이 달라진다.**

특히 **낙선자·전직 의원**이 그렇다. 현직은 공적 감시 대상이지만
30년 전 한 번 당선됐던 사람은 다르다.

- 인물 카드에 **개인 신상**(생년월일·주소·연락처)을 넣지 않는다.
  `ALLNAMEMBER` 에 `BIRDY_DT` `NAAS_TEL_NO` `NAAS_EMAIL_ADDR` 가 실제로 온다.
  **받되 내보내지 않는다.** 창고에는 원본이 남고 지도로는 안 나간다
- 매퍼가 이 필드들을 `member` 표에 넣지 않는다. 넣으면 언젠가 화면에 샌다

### 5-3. 정당명이 바뀐다 — 합치는 것도 판단이다

새누리당 → 자유한국당 → 미래통합당 → 국민의힘.
`POLY_NM` 은 **그 시점 값**이라 정확하다. 그대로 쓰면 사실이다.

그런데 여러 대수에 걸쳐 집계하면 **같은 흐름이 네 이름으로 쪼개진다.**
합치면 보기 좋지만 **합치는 순간 그건 우리의 편집 판단**이다.

- 법안 하나의 표결 집계는 **그 시점 이름 그대로** 쓴다. 판단이 안 들어간다
- 대수를 넘는 집계는 **지금 하지 않는다**
- 나중에 한다면 `party_side` 표처럼 **근거(src) 를 적은 표**로 두고
  화면에 "○○당 계열로 묶어 셈" 을 밝힌다

### 5-4. 실수로 잘못 누른 표결을 구별할 수 없다

전자투표라 오투표가 실재한다. 정정 기록이 남는 경우도 있다.
**우리는 구별 못 한다.** 그래서 한 건의 표결로 사람을 규정하지 않는 화면을 만든다 —
전체 결과를 같이 보여주는 것(4장)이 그 장치다.

### 5-5. `[표결 1,203건]` 이 인물 카드를 무겁게 만든다

한 사람이 1,203건이면 인물별 JSON 이 수백 KB 다. 3,295명이면 전체는 크다.
- 카드 열 때 받는다 (처음부터 다 받지 않는다)
- 목록은 **끊어서** 보여준다. `1,203건 중 20건` 처럼 **분모를 항상 낸다**
- 더 보기를 눌러야 다음이 온다

### 5-6. 여기서도 "0 은 의심한다"

`반대 0` 은 "아무도 반대 안 했다" 와 "표결 데이터를 아직 못 받았다" 를 구별하지 않는다.
**둘을 다르게 그린다.**

```
반대 0                   ← 표결을 받았고 반대가 없었다
표결 확인 중              ← 아직 안 받았다
표결 없음 · 상임위 계류    ← 본회의에 안 올라갔다
```

세 번째가 특히 중요하다. **본회의에 못 간 법안이 실패한 법안의 대부분**인데
`반대 0` 으로 그리면 통과된 것처럼 보인다.

## 5-7. 설명문이 비어 있는 노드 19개 — 채우지 않는다

전부 인물 연표 점이다. `퇴임` · `제15대 대통령 당선` · `해양수산부 장관` ·
`서강대 전자공학과 졸업` · `비상계엄 선포` 같은 것들이고, 이어진 것이 하나씩이다.

**제목 자체가 설명이다.** 문장을 억지로 붙이면 "2003년 2월 퇴임했습니다" 처럼
같은 말을 두 번 하게 된다. 비워 두는 것이 맞다.

빈 칸이 나중에 "채우다 만 것" 으로 보이지 않게 여기 적어 둔다 —
**의도해서 비운 것이다.**

### 한 줄 설명(tip)이 제목과 같은 것 23개는 화면에서 뺐다

같은 인물 연표에서 `tip` 이 `lab` 과 글자까지 똑같았다.
카드에 같은 말이 두 줄로 나오는 건 그냥 버그다.

**데이터는 그대로 두고 렌더에서 거른다** (`tipOf()`).
원본을 지우면 나중에 왜 비었는지 모른다.
**검사 31번**이 강제한다 — 거르는 경로가 사라지면 FAIL 이고,
카드 본문을 실제로 읽어 같은 말이 두 번 나오는지도 센다.

## 6. 안 하는 것

- 의원 순위·점수·등급
- "이 사람이 반대한 법안만" 같은 한쪽 필터
- 법안 카드의 찬성자·반대자 개인 이름 목록
- 개인 신상(생년월일·연락처·주소)
- 대수를 넘는 정당 집계
- "당론 이탈" 배지
- 발의 건수 기준 정렬

**하나하나가 만들기 쉽고 눌리기 좋은 기능이다.** 그래서 적어 둔다.
적어두지 않으면 어느 날 "그거 있으면 좋겠는데" 로 들어온다.

## 7. 만들기 전에 확인할 것

수집이 끝나야 알 수 있는 것들이다. **추측으로 화면을 만들지 않는다.**

1. `RESULT_VOTE_MOD` 값의 **종류를 전부** 뽑는다. 불참이 행으로 오나
2. 표결이 있는 법안이 몇 건인가. `발의 18,862건 중 표결 ?건`
3. 한 사람의 표결 최대 건수. 1,203 이 맞나
4. 공동발의자 수 분포. 평균 10명이 맞나
5. `PROC_RESULT` 값의 종류. `가결 / 부결 / 폐기 / 대안반영폐기` 등
6. 소속 정당 3명 이하인 정당이 몇 개인가 (0장의 역산 문제)
