## 1. 결과 노드 19개가 병목인 이유

사이트 이름이 '왜'다. 사용자는 **결과 숫자에서 출발한다.**
"집값이 5.36% 올랐다 → 왜?" 이 질문이 지도의 입구다.
법안은 입구가 아니라 그 뒤에 나오는 답이다.

그래서 **입구 개수 = 결과 노드 개수**다. 지금 입구가 19개뿐이다.

### 숫자로 보면

| | 개수 | 역할 |
|---|---|---|
| 결과(`result`) | **19** | 입구. 사용자가 검색해서 들어오는 지점 |
| 법안(`bill`) | 26 | 답. 입구를 통과한 뒤 보이는 것 |
| 사람·기관·사건 | 나머지 | 맥락 |

법안을 26개에서 50개로 늘려도 **입구는 그대로 19개다.**
들어올 문이 안 늘어나는데 안쪽 방만 늘리는 셈이다.

### 왜 결과가 성장 단위인가

1. **검색 유입이 결과 숫자에서 온다.** 사람들은 "종부세법 개정안"을 검색하지 않는다.
   "집값 얼마나 올랐나", "전세 왜 이래", "출산율" 을 검색한다.
   결과 노드 1개 = 유입 경로 1개.

2. **결과가 있어야 인과 관계를 걸 수 있다.** 관계 307개 중 `role='result'` 가 63개다.
   결과 노드 19개에 63개가 몰려 있다. 결과 1개당 평균 3.3개.
   결과가 없으면 법안은 서로 연결될 곳이 없어서 고립되거나
   사람·정당에만 붙는다 — 그러면 인과관계 지도가 아니라 인물 관계도가 된다.

3. **규칙 4를 지킬 자리가 결과 카드다.** 교란 요인은 결과 카드에 적는다.
   결과가 적으면 "시간 순서를 인과관계로 단정하지 않는다"를 보여줄 지면 자체가 적다.

### 그런데 지금 당장 못 채운다

결과 숫자는 대부분 **KOSIS(국가통계포털)** 쪽이다. 국회 의안정보와는 다른 출처,
다른 API, 다른 인증키다. 인증키가 아직 없다.
법안·발의·표결은 국회 열린국회정보 쪽이고, 이것도 키가 없다.

**결론: 결과 노드가 병목인 건 맞지만, 지금 손으로 채우는 건 답이 아니다.**
손으로 19개를 40개로 만들면 규칙 2(확인 안 된 숫자 금지)를 지키는 데
드는 시간이 폭증하고, 그 사이 규칙 5(진영 균형)는 더 기운다.
**수집기가 먼저다.** 그래서 아래 순서가 이렇게 된다.

## 2. 결과 숫자 1개를 추가하는 절차

노드 하나 늘리는 게 아니다. 아래 네 단계를 **전부** 통과해야 한다.
하나라도 못 채우면 넣지 않는다. 넣지 않는 게 기본값이다.

### 1단계 · 출처 확인

- **원자료를 먼저 찾는다.** 보도자료가 아니라 통계 원본.
  KOSIS, e-나라지표, 한국은행 경제통계시스템, 각 부처 통계연보.
- 기사에서 본 숫자는 출처가 아니다. 기사가 인용한 **원 통계표**까지 내려간다.
- 원자료에서 확인해야 하는 것:
  - 정확한 값 (반올림 전 원값)
  - 기준 시점 (연도·분기·월, 그리고 "언제 기준으로 집계한 값인지")
  - 조사 기관과 조사명
  - **직전 기간 값** — 비교 대상이 없으면 숫자가 의미를 못 가진다
- 값을 못 찾으면 `'확인 중'` 으로 두고 다음 단계로 가지 않는다.
  빈칸은 정직해 보이지만 틀린 숫자는 거짓말로 보인다. (규칙 2)

### 2단계 · 인과 후보 세우기

- **결과에서 거꾸로 간다.** "이 숫자가 왜 이렇게 됐나."
- 후보를 **여러 개** 세운다. 하나만 세우면 그게 곧 단정이 된다.
- 각 후보마다 확인할 것:
  - 시간 순서가 맞는가 (원인이 결과보다 **먼저**인가)
  - 공식 기록이 있는가 (법률 공포일, 시행일, 예산 집행, 판결 확정)
  - 관계에 붙일 **근거**(`l[5]`)가 있는가 — 없으면 그 관계는 만들지 않는다
- **역할(`role`)을 여기서 정한다.**
  - `result` — 근거 있는 인과 후보
  - `term` — 재임·여당·집권. "그때 정권"이지 "그 사람이 했다"가 아니다
  - `lead` — 실제 발의·주도. **재임을 근거로는 절대 붙이지 않는다** (규칙 3)
  - `against` — 반대·대립
- 대통령을 붙일 때는 **공포일자 × 재임표 계산으로만** 만든다.
  발의자·소관부처 필드에서 대통령을 끌어오지 않는다. 그런 코드 경로를 두지 않는다.

### 3단계 · 교란 요인 쓰기

- 결과 카드에 **반드시** 함께 적는다. 이건 선택이 아니다. (규칙 4)
- 같은 기간에 그 숫자를 움직였을 다른 요인:
  금리, 유동성, 인구 구조, 국제 정세, 환율, 원자재, 기저효과, 통계 기준 변경.
- 통계 원문이 스스로 밝힌 배경 설명이 있으면 그걸 먼저 쓴다.
  (예: r6은 정부 통계가 초저금리·유동성·전세가율·매수심리를 함께 들고 있다.)
- 문장은 단정을 피한다. "때문이다"가 아니라 "함께 작용했다".

### 4단계 · 링크 검증

- `official2` 에 원자료 링크를 넣는다. `[제목, URL, 설명]` 형식.
- **실제로 열리는지 확인한다.** 검색 결과에 URL이 떴다는 것만으로는 부족하다.
- `npm test` 10번 검사가 자동으로 HEAD 요청을 보낸다.
  - HEAD가 실패하면 GET으로 재확인한다 (law.go.kr은 HEAD에 404, GET에 200을 준다)
  - 403·429는 봇 차단이므로 WARN — **사람이 직접 열어봐야 한다**
  - 404·410·5xx는 FAIL
- `src` 필드도 채운다. 없으면 FAIL. (규칙 7)

### 마지막 · npm test

```bash
npm test
```

FAIL 0을 확인하고 커밋한다. 통과하지 못한 건 커밋하지 않는다.

## 3. 창고(SQLite)와 지도(렌더링)를 나누는 이유

지금은 `index.html` 한 파일에 **데이터와 화면이 같이 들어 있다.** 293KB.
231개까지는 이래도 돌아간다. 앞으로는 안 된다.

### 나누는 이유

**1. 검증을 데이터에 걸 수 있다**

지금 규칙 검사는 브라우저를 jsdom으로 띄워서 `window.N`, `window.L` 을 읽는다.
데이터를 보려고 렌더링 엔진을 통째로 부팅한다는 뜻이다.
검사 한 번에 4개 해상도 × 부팅이 필요하고, 화면 코드가 깨지면 데이터 검사도 같이 죽는다.
창고가 따로 있으면 SQL 한 줄로 끝난다 —
`SELECT id FROM node WHERE src IS NULL` 이 곧 규칙 7이다.

**2. 출처를 행 단위로 붙일 수 있다**

지금 `src` 는 노드에 붙은 문자열 한 줄이다.
"어느 필드의 어느 값이 어느 출처에서 왔는지"는 기록되지 않는다.
API로 수집을 시작하면 한 노드의 값들이 서로 다른 출처에서 온다 —
법안 제목은 의안정보, 표결은 열린국회, 결과 숫자는 KOSIS.
**수집 시각과 원본 응답까지 남겨야** 나중에 "이 숫자 어디서 났냐"에 답할 수 있다.
이게 신뢰의 실체다. 노드 필드 하나로는 감당이 안 된다.

**3. 수집이 반복되기 때문이다**

API 수집기는 같은 데이터를 주기적으로 다시 가져온다.
값이 바뀌었을 때 **무엇이 언제 바뀌었는지** 남아야 한다.
통계는 조용히 개정된다 — 잠정치가 확정치로 바뀌고, 기준연도가 변경된다.
파일 하나를 덮어쓰면 그 이력이 사라진다.
사라지면 "우리가 예전에 틀린 숫자를 실었었다"를 스스로 알 수 없다.

**4. 나라가 늘어난다**

한국판 다음은 미국·일본이다. 데이터 구조는 노드·관계·역할 세 가지로 동일하다.
같은 스키마에 `country` 만 다른 행을 넣으면 된다.
HTML 파일을 나라마다 복제하면 세 벌의 렌더링 코드를 각각 고치게 된다.

**5. 화면이 데이터를 못 바꾸게 만든다**

이게 가장 중요하다. 규칙 3이 깨지는 방식은 언제나 코드 경로다 —
발의자 필드에서 대통령을 끌어오는 한 줄이 `lead` 관계를 자동 생성한다.
창고와 지도가 분리되어 있으면 **렌더링은 읽기만 한다.**
관계를 만드는 건 창고 쪽 한 곳뿐이고, 검사는 그 한 곳만 보면 된다.
규칙을 지킬 자리가 하나로 줄어든다.

### 나누지 *않는* 것

- **배포 산출물은 여전히 정적 파일이다.** 창고는 빌드 시점에만 쓴다.
  사용자 브라우저가 SQLite에 접속하는 구조가 아니다.
  서버가 없어야 무료로 계속 굴릴 수 있고, 서버가 없어야 죽지 않는다.
- 창고 → 빌드 → 정적 JSON(또는 임베드) → 지도. 이 방향으로만 흐른다.

## 4. 다음 순서

### 1) 배포 — 먼저

**왜 먼저인가.** 지금 `index.html` 은 이미 동작한다. 231개 노드, 307개 관계,
FAIL 0. 이걸 아무도 못 보는 상태로 계속 고치는 건 위험하다.
쓰는 사람이 없으면 무엇이 안 읽히는지, 무엇이 안 눌리는지 알 수 없다.

정적 파일 하나라 배포가 가장 싼 단계다. 여기서:

- 실제 기기에서 확인한다 (실물 브라우저 확인에서 나온 문제들이 있다 — 아래 참고)
- 링크 검증을 온라인에서 정기적으로 돌린다. 링크는 시간이 지나면 죽는다
- 파일명이 한글(`index.html`)이다. URL 인코딩이 필요하다. 배포 시 정리할 것

**배포 전 UI 점검** — 실물 브라우저 확인에서 나온 것들. 원인까지 확정하고 대부분 고쳤다.

| 문제 | 어디서 | 원인 | 상태 |

| 이름표가 작아서 안 읽힘 | 1440·1920 | 이름표가 카메라 배율에 곱해져 그려짐. 12px × cam.s → 6.5px / 8px | **남음** — 아래 참고 |
| 이름표끼리 겹침 | 전 해상도 | 291 / 287 / 293 / 278쌍 | **남음** — 아래 참고 |

**점검 스크립트의 사각지대도 같이 드러났다.**
`check.cjs`는 "겹침 0"으로 통과시키고 있었는데, 실제로 겹치는 건 노드 원이 아니라
**이름표 박스**였다. 원 중심거리만 재고 있었다.
게다가 canvas 스텁의 `measureText`가 글자수 × 6.2px이라 한글 폭을 절반으로 재고 있었다.
**검사가 화면을 봤다고 착각하게 만드는 게 제일 위험하다.** 둘 다 고쳤고,
이제 이름표 박스 겹침 · 실제로 그려지는 이름표 수 · 화면상 글자 크기를 매번 출력한다.
값이 실물과 맞는다 (jsdom 291쌍 : 브라우저 268쌍).

### 남은 것 — 이름표 겹침과 큰 화면 글자 크기

폰·폴드는 배율을 1.0으로 고정해 12px을 확보했지만, 1440·1920은 여전히 6.5~8px다.
그리고 이름표를 키운 결과 **겹침이 전 해상도에서 280~290쌍**이 됐다.
이건 예상된 것이다 — 배율을 올려 이름표를 보이게 하는 단계(C)를 먼저 했고,
겹침 해소(A)는 다음이다.

A 단계에서 할 일:
- 이름표 폰트를 `12/cam.s`로 바꿔 화면상 크기를 배율과 무관하게 고정한다.
  [index.html:2328](../index.html:2328)에 이미 같은 패턴이 있다 — 국소적 변경이다.
- 겹치면 우선순위가 낮은 이름표를 숨긴다. 우선순위는 결과 > 법안 > 사람 > 사건,
  같은 종류면 연결이 많은 순.
- 그다음 이름표 겹침 WARN을 **FAIL로 승격**한다. 지금 WARN인 이유는 미결이라서다.

참고로 **필터를 걸면 문제가 대부분 사라진다.** 간첩·기밀을 고르면
배율이 0.54 → 0.85로 오르고 겹침이 293쌍 → 2쌍이 된다.
겹침은 "분야 전체를 한 화면에" 볼 때만 심각하다.

### 2) 렌더링 분리 — 다음

배포해서 실제 반응을 본 뒤에 한다. 순서가 중요하다:
**쪼개기 전에 배포하고, 배포한 것으로 무엇이 문제인지 확인한 다음 쪼갠다.**
안 그러면 아무도 안 쓰는 코드를 예쁘게 정리하는 데 시간을 쓴다.

- 데이터(`N`, `L`)를 HTML에서 떼어낸다
- 렌더링·물리·카드를 각각 분리한다 (200~400줄, 최대 800줄)
- **정규식으로 코드 블록을 잘라내지 않는다.** 문법 검사는 통과하는데
  함수가 통째로 날아간다. 실제로 그런 사고가 한 번 났다.
  jsdom으로 띄워서 확인하고, 4개 해상도를 매번 돌린다
- 이 단계가 끝나면 `check.cjs` 의 데이터 검사가 브라우저 부팅 없이 돌아간다

### 3) API 수집기 — 마지막

**인증키가 나온 뒤에 시작한다.** 지금은 키가 없다.

필요한 키:
- **열린국회정보 / 의안정보시스템** — 법안, 발의자, 소관위, 표결
- **KOSIS(국가통계포털)** — 결과 숫자. 여기가 병목을 푸는 열쇠다
- **국가법령정보센터** — 법령 원문, 공포일자·시행일자

수집기가 돌기 시작하면 자동으로 풀리는 것들:

- **결과 노드 19개 병목** — KOSIS에서 통계 계열 단위로 들어온다
- **진영 기울기 25.7%** (진보 93 : 보수 55) — 발의·표결 데이터가 채워지면 완화된다.
  **손으로 맞추지 않는다.** 손으로 맞추면 균형이 아니라 연출이다
- **official2 링크 3개** — 법령·의안 원문 링크가 노드마다 자동으로 붙는다
- **`limit` 빈칸 4개** (b6·b7·b9·b11) — 이건 자동화가 안 된다.
  비판·한계는 사람이 읽고 써야 한다. 4개가 채워지면 WARN을 FAIL로 승격한다

**수집기가 지켜야 할 것 (규칙 3):**
발의자·소관부처 필드에서 대통령을 끌어오는 코드 경로를 **아예 만들지 않는다.**
대통령 관계는 공포일자 × 재임표 계산으로만 만든다.
수집기는 이 규칙이 가장 쉽게 깨지는 지점이다 — API 응답에 대통령 이름이 들어 있고,
그걸 그대로 노드로 만들면 "재임 중"이 "밀어붙임"으로 자동 변환된다.
