# 노드를 눌렀을 때 이어진 것을 화면 안으로

**제안만 한다. 아직 안 고쳤다.**

---

## 문제

폰에서 사건을 누르면 이어진 것들이 화면 밖에 있다. 실측:

| | 이어진 것 | 화면 안 |
|---|---:|---:|
| 폰 412×915 | 6 | **2 (33%)** |
| 폴드 접음 344×882 | 6 | **2 (33%)** |
| 아이패드 세로 820×1180 | 6 | **3 (50%)** |
| 갤탭 세로 800×1280 | 6 | **3 (50%)** |
| 가로 화면 전부 | 6 | 6 (100%) |

**폰만의 문제가 아니라 세로 화면 전부의 문제다.**

---

## 먼저 — 위치가 무엇을 뜻하는지 정확히

"노드 위치가 시간(연도)을 뜻한다" 고 하셨는데, 코드를 보니 **절반만 그렇다.**

```js
function ringR(n){ return radY(pyOf(n)) }   // 반지름 = 연도
function setAngles(){
  var arr = A.slice().sort(...연도순...);
  arr.forEach(function(n,i){ n.ang = i * 2.39996 })   // 각도 = 황금각 × 순번
}
```

| | 뜻 |
|---|---|
| **반지름** | **연도다. 의미가 있다** |
| **각도** | **아무 뜻이 없다** |

각도는 황금각(2.39996 rad)으로 흩뿌린 값이다. 고르게 퍼뜨리는 장치일 뿐이고,
오히려 **연도가 가까운 노드일수록 각도를 멀리 떨어뜨린다** (137.5° 씩 건너뛴다).
같은 각도에 있는 두 노드가 무슨 관계라는 뜻이 전혀 아니다.

**그래서 각도를 돌리는 것은 동심원의 의미를 깨지 않는다.**
깨는 것은 **반지름을 바꾸는 것**뿐이다.

이게 아래 B안이 안전한 이유다. 걱정하신 지점이 정확했고,
다만 **반지름만 지키면 된다**는 게 코드를 읽고 나온 답이다.

---

## A안 — 카메라를 움직인다 (누른 노드 중심으로 확대·이동)

노드는 그대로 두고 카메라만 옮긴다. **가장 안전하다. 의미를 전혀 안 건드린다.**

### 그런데 폰에서는 안 된다 — 실측

이어진 6개를 다 담으려면 이만큼 줄여야 한다:

| | 필요 배율 | 이름표(이웃 6) |
|---|---:|---:|
| 폰 412×915 | **0.24** | **2/6** |
| 폴드 접음 | **0.20** | **2/6** |
| 갤탭 세로 | 0.55 | 3/6 |
| 아이패드 세로 | 0.65 | 5/6 |

이름표 하한(`LABEL_FAR` = 0.62)의 **절반도 안 된다.**
**연결은 보이는데 이름이 없는 화면**이 된다. 색깔 점 6개만 남는다.

문제를 푼 게 아니라 옮긴 것이다.

**작은 화면에서 A안 단독은 안 된다.** 큰 화면에서는 이미 100% 라 필요도 없다.

---

## B안 — 각도만 모은다. 반지름(연도)은 그대로

이어진 노드들의 **각도를 누른 노드 쪽으로 회전**시킨다.
**반지름은 손대지 않는다** — 연도가 정확히 보존된다.

```
누른 노드 각도 a0
이웃 i 의 새 각도 = a0 + (i - (n-1)/2) × 벌림
이웃 i 의 반지름 = ringR(n)          ← 그대로. 연도다
```

### 실측 — 폰에서 배율이 0.24 → 0.96 으로

부채꼴 벌림 각도를 바꿔가며 폰(412×915)에서 쟀다:

| 벌림 | 필요 배율 | 이름표(전체) | 이름표(이웃 6) |
|---:|---:|---:|---:|
| 0.10 rad | 0.96 | 60/171 | 3/6 |
| 0.16 | 0.63 | 28/171 | 3/6 |
| **0.24 (약 14°)** | **0.96** | **58/171** | **4/6** |
| 0.34 | 0.77 | 47/171 | 4/6 |
| 0.46 | 0.52 | 13/171 | 5/6 |
| 0.60 | 0.36 | 9/171 | 4/6 |

**0.24 rad 이 최적이다.** A안 대비 배율 4배, 이름표 12배(5/171 → 58/171).

벌림이 너무 크면 다시 멀어져 이름표가 끊긴다. 0.46 부터 하한 밑으로 떨어진다.

> 숫자가 오르내리는 건 물리가 매번 조금 다르게 안정되기 때문이다.
> **각 값은 1회 측정이다.** 구현할 때 여러 번 돌려 평균을 봐야 한다.

### 덤 — 거리가 뜻을 갖게 된다

각도를 모으면 남는 거리는 **반지름 차이뿐**이고, 반지름은 연도다.
즉 **화면상 거리가 곧 연도 차이**가 된다. 지금은 아무 뜻 없는 거리인데,
모으고 나면 "가까이 있는 건 비슷한 시기" 가 된다. 정보가 늘어난다.

### 위험

- **돌아가는 길이 확실해야 한다.** 다른 데를 누르거나 닫으면 원래 각도로 복귀.
  `setAngles()` 가 결정적(연도 정렬 + 황금각)이라 언제든 정확히 되돌릴 수 있다
- **애니메이션 없이 순간이동하면 어지럽다.** 0.3~0.4초로 돌린다
- 각도를 옮긴 노드가 **다른 노드와 겹칠 수 있다.** 기존 충돌 해소가 밀어내는데,
  그 밀어냄이 반지름을 건드린다 — **반지름을 다시 고정하는 항이 필요하다**

마지막 항목이 실제 구현의 핵심이다. 지금 물리에는
`fx += (tx-n.x)*0.055` 로 목표 위치로 당기는 항이 이미 있으니 목표만 바꾸면 되지만,
그 뒤 충돌 해소 8회가 위치를 밀어낸다. **충돌 해소 뒤 반지름을 원래 값으로 되돌리는
한 줄**이 있어야 연도가 안 흔들린다.

## C안 — 이어진 것만 남기고 나머지를 잠시 감춘다

카메라·위치를 안 건드린다. **`focus` 일 때 이웃이 아닌 노드를 안 그린다.**
그러면 `fit()` 이 이웃만 담으면 되므로 필요 배율이 훨씬 커진다.

- 가장 적게 건드린다. 의미 훼손 0
- 이미 `ring[n.id]` 로 이웃을 구분하고 있어 붙이기 쉽다
- **단점: 맥락이 사라진다.** 이 사이트는 "주변에 뭐가 있었나" 를 보여주는 지도인데
  주변을 지우면 지도가 아니라 목록이 된다
- 되돌아올 때 방향 감각을 잃는다 — 화면이 통째로 바뀌어서

---

## 제안 — **B + A 합본. C 는 안 한다**

```
노드를 누르면
  1. 이웃의 각도를 누른 노드 쪽으로 0.24 rad 부채꼴로 모은다 (B)
     반지름은 그대로. 연도는 안 흔들린다
  2. 물리가 안정된 뒤 카메라를 그 부채꼴에 맞춘다 (A)
     이때 필요 배율이 0.96 이라 이름표가 살아 있다
  3. 닫거나 다른 데를 누르면 setAngles() 로 정확히 복귀
```

- **폰 · 세로 태블릿**: B 가 필수다. A 단독은 배율 0.24 라 이름이 사라진다
- **가로 · 데스크톱**: 이미 100% 다. B 를 적용하되 A 는 약하게

C 를 안 하는 이유: **맥락을 지우는 건 이 사이트의 목적과 반대다.**

---

## 먼저 정할 것 — 구현 전에

1. **B 를 큰 화면에도 적용하나?**
   가로에서는 이미 100% 라 필요 없다. 다만 **기기마다 다르게 움직이면**
   같은 사이트를 다른 것처럼 느낀다. 통일하는 쪽이 나아 보이는데 판단이 필요하다
2. **부채꼴을 어느 쪽으로 펴나?** 화면 안쪽으로 펴야 잘 보인다.
   누른 노드가 화면 오른쪽에 있으면 왼쪽으로 펴는 식
3. **이웃이 6개보다 적을 때는?** 2~3개면 벌림을 넓혀도 된다. 개수에 따라 조정
4. **되돌아갈 때 애니메이션 시간** — 0.3초 정도로 시작

## 검사에 넣을 것

이 문제를 지금까지 아무도 못 잡은 이유는 **재는 검사가 없어서**다.

```
노드를 눌렀을 때 이웃이 화면 안에 몇 개인가 · 분모와 함께
  폰 412×915 · 화면 안 2/6 (33%)      ← 지금
  폰 412×915 · 화면 안 6/6 (100%)     ← 고친 뒤
```

그리고 **반지름이 안 흔들렸는지 검사한다** — B안의 유일한 위험이다.

```
각도를 모은 뒤 모든 노드의 반지름이 ringR(n) 과 같은가
  다르면 FAIL. 연도가 흔들렸다는 뜻이다
```

**실패 주입도 같이 한다** — 반지름을 일부러 5% 틀어놓고 이 검사가 FAIL 하는지 본다.
