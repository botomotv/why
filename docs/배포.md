# 배포 절차 — Cloudflare Pages

`index.html`은 서버가 필요 없는 정적 파일 하나다. 그래서 배포가 싸고, 죽지 않고, 공짜다.
서버가 없어야 무료로 계속 굴릴 수 있다.

**소요 시간: 처음 한 번 30~40분.** 그다음부터는 `git push` 하면 자동으로 올라간다.

> **주의 — 화면이 문서와 다를 수 있다.**
> Cloudflare는 대시보드 메뉴 이름을 자주 바꾼다. 버튼 이름이 안 보이면
> **비슷한 뜻의 버튼**을 찾으면 된다. 각 단계마다 "무엇을 하려는 것인지"를 같이 적어뒀다.

## 0단계 · 배포 전 준비 — **끝났다**

아래는 이미 처리했다. 확인만 하면 된다.

| 항목 | 상태 |
|---|---|
| `왜.html` → `index.html` | **완료.** 웹 서버는 주소 끝이 `/`일 때 `index.html`을 찾는다. 안 바꿨으면 루트가 404였다 |
| `test/check.cjs` 경로 | **완료** |
| README · CLAUDE.md · docs 안의 파일명 | **완료.** `왜.html`이 남아있는 곳이 하나도 없다 |
| `.gitignore`에 `node_modules/` | **완료** |
| 브라우저 탭 제목 | **완료** — `이 숫자, 왜 이렇게 됐나` |
| 파비콘 | **완료** — 외부 파일 없이 인라인 SVG(data URI). 금색 '왜' |
| `description` · `og:*` · `twitter:*` | **완료** — 아래 참고 |
| `robots.txt` | **완료** — 전체 허용 |

### 링크 미리보기 카드 — **끝났다**

도메인이 `why-map.com` 로 정해져서 넣었다. 카톡·트위터에 링크를 붙이면
`og.png` 가 큰 그림으로 뜬다 (`twitter:card` 는 `summary_large_image`).

**그림을 다시 만들려면** — 원본은 [docs/og.html](og.html) 이다. 사이트와 같은 색·폰트를 쓴다.

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=1 --window-size=1200,630 --screenshot=og.png --virtual-time-budget=6000 "file://$PWD/docs/og.html"
```

지켜야 할 규격 — `npm test` 15번 검사가 강제한다:

- **1200 × 630px**, PNG, 300KB 이하
- `og:image` 와 `og:url` 은 **절대 주소**. 상대 경로는 크롤러가 못 읽는다
- 저장소 루트에 파일이 실제로 있어야 한다
- **가장자리 100px 안쪽에는 글자를 두지 않는다.** 카카오톡이 잘라서 보여준다
  (지금 파일은 안전 영역 밖 밝은 픽셀 0개를 픽셀 단위로 확인했다)

### `pages.dev` 를 새 도메인으로 넘기기

도메인을 붙여도 `why-143.pages.dev` 는 계속 열린다.
**같은 내용이 두 주소로 열리면 검색엔진이 중복 콘텐츠로 보고** 어느 쪽을 정본으로 삼을지
스스로 고른다. 우리가 정해줘야 한다.

**① `canonical` — 이미 넣었다**

```html
<link rel="canonical" href="https://why-map.com/">
```

`pages.dev` 로 들어와도 "정본은 why-map.com" 이라고 검색엔진에 알린다.
이것만으로도 색인 문제는 대부분 정리된다. `npm test` 16번 검사가 도메인이 어긋나면 잡는다.

**② 실제로 넘기려면 — Cloudflare 규칙 (권장)**

1. Cloudflare 대시보드 → 왼쪽 **Rules** → **Redirect Rules** → **Create rule**
2. **Rule name**: `pages.dev → why-map.com`
3. **When incoming requests match** → **Custom filter expression**
   - Field `Hostname` · Operator `equals` · Value `why-143.pages.dev`
4. **Then** → **Type** `Dynamic`
   - Expression: `concat("https://why-map.com", http.request.uri.path)`
   - **Status code** `301` (영구 이동)
   - **Preserve query string** 체크
5. **Deploy**

`301` 이라야 검색엔진이 색인을 옮긴다. `302` 는 임시라 안 옮긴다.

> 메뉴 이름은 Cloudflare 가 자주 바꾼다. **Rules** 아래에서 "리다이렉트" 뜻의 항목을 찾으면 된다.

**③ `www` 도 함께**

`www.why-map.com` 으로도 접속되는 것을 확인했다. 둘 다 열리면 같은 문제가 생긴다.
위와 같은 방식으로 `www` 를 `why-map.com` 으로 넘기거나, 반대로 `www` 를 정본으로 삼고
`canonical` 을 `https://www.why-map.com/` 으로 바꾼다. **어느 쪽이든 하나로 정한다.**

### 도메인을 바꿀 때 — 고쳐야 하는 곳 전부

화면에 보이는 것(워터마크·카드 저작권·'보는 법' 안내)은 `index.html` 의
**`SITE` 상수 한 곳**에서 온다. 그런데 `<head>` 메타는 크롤러가 JS 실행 전에 읽어야 해서
HTML 에 박아야 하고, 링크 카드 그림과 문서는 별도 파일이다.
정적 파일에서 이건 피할 수 없다.

대신 **한 곳을 고치면 `npm test` 16번 검사가 나머지를 전부 이름까지 지목한다.**
`SITE.host` 를 바꾸고 `npm test` 를 돌린 다음, FAIL 목록이 비워질 때까지 고치면 된다.

| 어디 | 무엇 |
|---|---|
| `index.html` | `SITE` 상수의 `host` ← **여기부터** |
| `index.html` `<head>` | `og:url` · `og:image` · `twitter:image` |
| `docs/og.html` | 아래쪽 도메인 표기 → **고친 뒤 `og.png` 다시 렌더** |
| `README.md` | 출처 표시 예시 |
| `LICENSE` | 출처 표시 예시 |
| `docs/배포.md` | 이 문서 |

**`robots.txt` 의 사이트맵 줄**은 아직 주석 처리돼 있다. 사이트맵을 만들면 그것도.

**바꾼 뒤에는 카카오톡 캐시를 지워야** 새 카드가 보인다:
[카카오 디버거](https://developers.kakao.com/tool/debugger/sharing)에 주소를 넣고 **초기화**.
트위터는 [Card Validator](https://cards-dev.twitter.com/validator).

## 1단계 · GitHub에 저장소 만들기

GitHub는 코드를 올려두는 곳이다. Cloudflare가 여기를 보고 자동으로 사이트를 만든다.

### 1-1. GitHub 계정

[github.com](https://github.com) → 계정이 없으면 **Sign up**.

### 1-2. 빈 저장소 만들기

1. 오른쪽 위 **`+`** 버튼 → **New repository**
2. **Repository name**: `why` (아무거나 괜찮다)
3. **Description**: `한국 정치·정책 인과관계 지도` (비워도 된다)
4. **Public** / **Private** 중 고른다
   - **Public 권장.** 무료 공개 사이트고, 출처를 검증받는 게 이 프로젝트의 자산이다.
   - Private으로 해도 Cloudflare Pages 배포는 된다.
5. 아래 세 개는 **전부 체크하지 않는다** — 이미 로컬에 파일이 있어서 충돌한다
   - ☐ Add a README file
   - ☐ Add .gitignore
   - ☐ Choose a license
6. 초록색 **Create repository** 버튼

### 1-3. 로컬 저장소를 GitHub에 연결

저장소를 만들면 화면에 명령어가 뜬다. 그중
**"…or push an existing repository from the command line"** 부분을 쓴다.

터미널에서 한 줄씩:

```bash
cd /Users/yongsuk/why
```

```bash
git remote add origin https://github.com/<네-계정이름>/why.git
```

`<네-계정이름>` 자리에 GitHub 아이디를 넣는다. GitHub 화면에 뜬 주소를 그대로 복사해도 된다.

```bash
git push -u origin main
```

**비밀번호를 물어보면** GitHub 계정 비밀번호가 아니라 **토큰**이 필요하다:
GitHub → 오른쪽 위 프로필 사진 → **Settings** → 맨 아래 **Developer settings** →
**Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)** →
**repo** 체크 → **Generate token** → 나온 문자열을 복사해서 비밀번호 자리에 붙여넣는다.

> 토큰은 한 번만 보여준다. 안 보이는 곳에 저장해두고, **절대 코드에 넣지 않는다.**

### 1-4. 확인

브라우저에서 `https://github.com/<네-계정이름>/why` 를 열어
`index.html`, `README.md`, `test/`, `docs/`가 보이면 성공이다.

## 2단계 · Cloudflare Pages 연결

### 2-1. Cloudflare 계정

[dash.cloudflare.com](https://dash.cloudflare.com) → **Sign up** (무료)
가입하면 이메일 인증 메일이 온다. 링크를 눌러 인증한다.

### 2-2. Pages 프로젝트 만들기

1. 왼쪽 메뉴에서 **Workers & Pages** 를 누른다
   - 메뉴 이름이 **Compute (Workers)** 로 보일 수도 있다. 둘 다 같은 곳이다.
2. **Create application** (또는 **Create**) 버튼
3. 위쪽 탭에서 **Pages** 를 고른다 — *Workers가 아니라 Pages다*
4. **Connect to Git** 버튼

### 2-3. GitHub 연결 허용

1. **GitHub** 를 고른다
2. **Install & Authorize** — GitHub 로그인 화면이 뜬다
3. 어느 저장소를 볼지 고른다
   - **Only select repositories** 를 고르고 `why` 만 선택하는 걸 권한다
   - **All repositories** 도 되지만 필요 이상으로 권한을 준다
4. **Install** / **Save**

### 2-4. 저장소 고르고 빌드 설정

1. 목록에서 `why` 를 고르고 **Begin setup**
2. 설정 화면이 나온다. **이 프로젝트는 빌드가 필요 없다.**

| 항목 | 넣을 값 |
|---|---|
| **Project name** | `why` (사이트 주소가 된다: `why.pages.dev`) |
| **Production branch** | `main` |
| **Framework preset** | **None** |
| **Build command** | **비워둔다** |
| **Build output directory** | `/` — 슬래시 하나만. (칸이 비어야 한다면 비워둔다) |

> `npm install`이나 `npm run build`를 넣지 않는다.
> `jsdom`은 검사용이지 사이트에 필요한 게 아니다. 넣으면 배포가 느려지기만 한다.

3. **Save and Deploy**

### 2-5. 배포 확인

1~2분 뒤 **Success!** 과 함께 주소가 뜬다: `https://why.pages.dev`
눌러서 지도가 뜨는지 확인한다.

**안 뜨면 여기부터 본다:**

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| 404 Not Found | `index.html`이 없다 | 0단계를 안 했다. 파일 이름을 바꾸고 다시 push |
| 흰 화면 | JavaScript 오류 | 브라우저에서 마우스 오른쪽 → **검사** → **Console** 탭의 빨간 글씨 확인 |
| 글꼴이 이상하다 | 웹폰트 차단 | 심각하지 않다. 나중에 |

## 3단계 · 도메인 연결

`why.pages.dev` 로도 충분히 쓸 수 있다. 직접 도메인을 붙이고 싶을 때만 한다.

### 3-1. 도메인 사기

Cloudflare에서 바로 살 수 있다: 왼쪽 메뉴 **Domain Registrar** → **Register Domain**
여기서 사면 아래 3-2를 건너뛴다. (`.kr`은 안 팔 수 있다. 그럼 가비아 등에서 산다)

### 3-2. 다른 곳에서 산 도메인이면 — Cloudflare에 등록

1. 대시보드 첫 화면 → **Add a domain** (또는 **Add site**)
2. 도메인 주소를 넣고 **Continue**
3. 요금제에서 **Free** 를 고르고 **Continue**
4. Cloudflare가 **네임서버 두 개**를 알려준다 (`xxx.ns.cloudflare.com` 모양)
5. **도메인을 산 곳**(가비아·후이즈 등)에 로그인 →
   **네임서버 설정** / **DNS 설정** 메뉴 → 기존 네임서버를 지우고 위 두 개를 넣는다
6. Cloudflare로 돌아와 **Check nameservers**

> 네임서버 변경은 **몇 분~48시간** 걸린다. 보통 1시간 안쪽이다. 기다리면 된다.

### 3-3. Pages에 도메인 붙이기

1. **Workers & Pages** → `why` 프로젝트를 누른다
2. 위쪽 탭에서 **Custom domains**
3. **Set up a domain** 버튼
4. 도메인 주소를 넣는다 (예: `why.kr`)
5. **Continue** → **Activate domain**

Cloudflare가 DNS 레코드를 자동으로 만든다. HTTPS 인증서도 자동이다.
**Active** 로 바뀌면 끝이다. 보통 몇 분 걸린다.

### 3-4. `www` 도 쓰려면

3-3을 한 번 더 하되 `www.why.kr` 을 넣는다. 둘 다 같은 사이트로 간다.

## 4단계 · 이후 배포

**끝났다. 이제 자동이다.**

```bash
git add -A
```

```bash
git commit -m "고친 내용 한 줄로"
```

```bash
git push
```

push하면 Cloudflare가 알아서 새로 배포한다. 1~2분이면 반영된다.

**push 전에 반드시:**

```bash
npm test
```

`결과: PASS`가 아니면 push하지 않는다. 배포된 사이트에 틀린 사실이 올라가는 게
이 프로젝트에서 가장 나쁜 일이다.

`npm test`의 10번 검사가 `official2` 원자료 링크에 실제로 요청을 보낸다.

한 달에 한 번은 온라인에서 `npm test`를 돌린다. 나중에 자동화할 수 있다.

지금까지 확인은 데스크톱 브라우저의 창 크기를 바꿔서 한 것이다.
**진짜 폰과 폴드로 한 번 열어봐야 한다.** 특히:

- 두 손가락 확대 / 드래그가 되는지
- '보는 법' 서랍이 손가락으로 잘 열리고 닫히는지
- 노드를 눌렀을 때 카드가 뜨는지

[README.md](../README.md)의 "아직 안 된 것"에 정리해뒀다.
이름표 겹침, 큰 화면 글자 크기, 결과 노드 19개, 첫 화면 설명 부재.
**배포를 미룰 이유는 아니다.** 아무도 안 보는 상태로 계속 고치는 게 더 위험하다.

## 왜 Cloudflare Pages인가

- **무료.** 대역폭 제한이 없다. 갑자기 사람이 몰려도 요금이 안 나온다.
  이 프로젝트는 광고도 후원도 안 받으므로 비용이 0이어야 지속된다.
- **서버가 없다.** 서버가 없으면 서버가 죽지 않는다. 관리할 것도 없다.
- **git push 하면 끝.** 배포 절차가 따로 없다.
- **HTTPS 자동.**

Netlify, Vercel, GitHub Pages 도 비슷하게 된다.
Cloudflare를 고른 이유는 무료 대역폭 제한이 없어서다.
